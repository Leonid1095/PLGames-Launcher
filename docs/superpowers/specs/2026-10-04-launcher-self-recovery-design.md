# Самовосстановление лаунчера (0.5.1)

Дата: 04.10.2026. Согласовано с владельцем в чате.

## Задача

Лаунчер сам приводит себя и игру в рабочее состояние:
1. откатывает собственное обновление, если новая версия не поднялась;
2. после сбоя посреди установки издания или аддонов откатывает клиент и продолжает установку;
3. замечает испорченные файлы издания и аддонов и ставит их заново;
4. проверяет файлы клиента игры и чинит битые, скачивая только их;
5. качает клиент не только у раздающих, но и с нашего сервера.

В тот же выпуск входят вкладки под каждую игру (`project_tabs`, уже сделано).

## 1. Откат плохого обновления

Скрипт обновления `_update.bat` пишет та версия, которая обновляется. Поэтому откат работает
начиная с обновлений, которые ставит 0.5.1.

**Скрипт после переноса файлов:**
- запускает новый exe и до 90 с ждёт файла-отметки `%APPDATA%\PLGamesLauncher\update-ok`;
- нет отметки, а процесс `PLGamesLauncher.exe` жив → он завис: процесс снимается;
- нет отметки → новый exe заменяется на `.bak`, прежняя версия запускается,
  в `%APPDATA%\PLGamesLauncher\update-failed.json` пишется версия, которая не поднялась.

**Лаунчер:**
- отметку пишет после того, как интерфейс загрузился (первый вызов `get_version` из JS);
- перед обновлением удаляет старую отметку;
- `check_update` не предлагает версию из `update-failed.json`, пока не выйдет более новая;
- на главном экране показывает «Обновление до X не запустилось — вернули прежнюю версию».

## 2. Сбой посреди установки

Сейчас журнал отката хранится только в памяти (замыкания). Теперь каждая запись журнала — данные:

| Запись | Отмена |
|---|---|
| `move` src → dst | перенести обратно |
| `config` previous | записать прежние значения в Config.wtf |
| `uninstall` (installer) | запустить `uninstall` пакета |

После каждого шага журнал пишется в `PLGames\apply-journal.json`. Рядом лежит `PLGames\pending.json`:
`{scope, target, edition}`, то есть что ставилось. Оба файла удаляются после успеха или полного отката.

При запуске (`EditionService.recover`), если журнал найден и игра не запущена:
- отменить записи с конца, удалить журнал. `state.json` при сбое не обновлялся, поэтому клиент
  снова совпадает с ним;
- если есть `pending.json` — запустить ту же установку заново. Скачанное лежит в кэше
  `PLGames\downloads`, повторно не качается.

## 3. Издание и аддоны

При установке у каждого файла компонента `files` запоминаются `size` и `mtime_ns` (в `state.json`).
`component_status`:
- размер другой или файла нет — `outdated` (так было и раньше);
- `mtime_ns` другой — считается SHA-256. Не совпал с манифестом — `outdated`, совпал — запоминается
  новый `mtime_ns`. Лишний хэш считается один раз.

Для аддонов (`zip`): нет папки или её `.toc` — `outdated`.

Автопочинка: при запуске лаунчера и перед запуском игры, если у активного компонента `outdated`,
лаунчер сам применяет текущий набор заново. План переустанавливает только устаревшее.

## 4. Клиент игры

**Индекс.** `tools/build_client_index.py` читает RAR5 клиента и пишет `client-index.json`:

```json
{"archive": "PLGames_Wow3.3.5.rar", "archive_size": 21069765019, "root": "PLGames_Wow3.3.5",
 "main_header": "<hex>", "files": [{"path": "Data/common.MPQ", "size": 2856083241,
 "crc32": "63c7bd6b", "offset": 123, "length": 2792542100}]}
```

`offset` и `length` указывают на заголовок файла вместе с упакованными данными. Архив без «solid»,
поэтому каждый кусок распаковывается отдельно. Индекс публикуется в `content-latest` и рядом с
архивом на сервере. Лаунчер берёт его, как манифест изданий: сервер → GitHub → кэш.

**Проверка** (`clientrepair.py`):
- быстрая — перед каждым запуском игры: все файлы на месте, размеры верны, CRC32 `Wow.exe`. Меньше секунды;
- полная — кнопкой «Проверить и починить» в настройках: CRC32 всех 379 файлов, с прогрессом и отменой.

Не считаются поломкой:
- `realmlist.wtf`, `WTF/`, `Interface/`, `Cache/`, `Screenshots/`, `Logs/`, `Errors/`;
- MPQ, которые выключило издание: файла нет, но есть `<имя>.disabled` нужного размера.

**Починка** битого или пропавшего файла. Источники по порядку:
1. Архив клиента на диске игрока (папка торрента, размер совпадает с индексом). Кусок читается с диска.
2. Архив на нашем сервере: `https://plgames-wow.ru/launcher/client/PLGames_Wow3.3.5.rar`,
   запрос `Range: bytes=offset-(offset+length-1)`.
3. Иначе — сообщение «скачайте клиент заново» с кнопкой загрузки по торренту.

Из куска собирается мини-архив: сигнатура RAR5 + главный заголовок из индекса + кусок + заголовок
конца архива. Его распаковывает имеющийся распаковщик (7-Zip или tar) во временную папку.
CRC32 сверяется, файл переносится на место. Проверено 04.10 на настоящем архиве:
`Battle.net.dll` (смещение 29) и `Wow.exe` (смещение 21 066 737 768) распаковались, CRC совпали.

## 5. Сервер в торренте

В `PLGames_Wow3.3.5.torrent` добавляется `url-list` (BEP 19):
`https://plgames-wow.ru/launcher/client/PLGames_Wow3.3.5.rar`. Поле лежит вне `info`, поэтому
info-hash не меняется и нынешние раздачи продолжают работать. aria2c качает и с сервера, и у раздающих.
Пока на сервере файла нет, aria2c просто пропускает этот источник.

## Серверная часть (выполняет владелец или сессия на сервере)

- Каталог `/home/plgames/launcher-files/` с подкаталогами `client/` и `content/`.
- Архив в `client/` скачивает сам сервер, по торренту, пока раздаёт ПК владельца.
- nginx: `location /launcher/ { alias /home/plgames/launcher-files/; }`. Range nginx отдаёт сам.
  Тот же каталог закрывает и `/launcher/content/`, который сейчас отвечает 404.
- В `content/` — `manifest2.json`, `client-index.json` и файлы изданий (копия `dist-content/server`).

## Проверка

Тесты на поддельных клиентах:
- откат скрипта обновления: функция, которая строит `.bat`, плюс прогон скрипта с фальшивым exe;
- обрыв посреди установки: исключение после N шагов, затем `recover`;
- изменённый файл издания;
- битый, пропавший и выключенный изданием файл клиента;
- починка из локального мини-архива: в `tests/fixtures/` — RAR5 из двух маленьких файлов,
  вырезанных из настоящего архива;
- Range-починка через поддельную сессию;
- `url-list` в торренте, info-hash прежний.

На настоящем клиенте — полная проверка и починка нарочно испорченной копии файла.
